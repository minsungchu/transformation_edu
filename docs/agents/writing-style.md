# 교재 글쓰기 스타일 가이드

교재(site/docs)의 모든 페이지가 따르는 문체 규칙. 새 챕터 집필과 기존 페이지 수정 모두 이 규칙을 Acceptance criteria로 삼는다.

## 기본 형태: 혼합형 개조식

- 절(section)의 구조
  - 도입: 프로즈 1~2문장 — 이 절이 "왜" 필요한지만
  - 본문: 들여쓰기 불릿 트리 — "무엇"은 전부 여기에
- 불릿 트리 작성법
  - 1레벨: `**라벨** — 핵심 요점` (명사형/짧은 구로 종결)
  - 2레벨: 속성을 키-값으로 — `위치:`, `역할:`, `의미:`, `예:` 등
  - 3레벨 초과 금지 — 더 깊어지면 절을 쪼갠다

## 헤딩·번호 규칙

- H1은 페이지 제목 1개뿐 — 본문에서 다시 쓰지 않는다
- 절 제목은 H2 + 순번: `## 1. 절 제목` (페이지마다 1부터)
- 하위 절은 H3 + 계층 번호: `### 1.1 하위 제목`
- 번호는 마크다운 텍스트로 직접 쓴다 (TOC·사이드바에도 번호가 보여야 하므로 CSS 카운터 금지)

## 문장 규칙

- 한 문장 = 한 정보
- 금지: 대시/괄호 삽입구를 문장 안에 겹쳐 넣기, 3개 이상 열거를 문장 안에 풀어쓰기
- 프로즈 문단은 최대 2~3문장 — 그 이상이면 불릿 트리로 전환

## 화면 밀도 규칙

- admonition 박스(tip/info/warning): **페이지당 최대 1개** — 정말 경고·주의가 필요한 곳만
- 표: 짧은 대응 관계만 — 셀 안에 수식이나 완결 문장을 넣지 않는다
- 강조(굵게)는 불릿 라벨과 핵심 용어에만

## 용어·병기 규칙

- 용어는 CONTEXT.md가 유일한 기준 (World 좌표계, Camera 좌표계, passive Euler, $T^{A}_{B}$ 표기)
- 영어 병기는 **챕터당 첫 등장 1회만**: "카메라(Sensor)" → 이후 "카메라" 또는 "Sensor" 단독
- 한→영 병기 금지: "기준(reference)" 같은 형태는 쓰지 않는다

## 수식·기호 규칙

- 기호는 해당 개념을 배우는 챕터에서 처음 정의하고, 이후 챕터는 정의 없이 사용
- 예외 — 0단계(전체 지도): 기호를 유지한다. 학습자가 나중에 돌아와 다시 읽는 지도이기 때문
- 수식 블록은 절당 1개를 넘기지 않는다 (계산 챕터 제외)
